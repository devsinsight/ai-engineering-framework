# Starting scenarios

The same principles apply in every scenario; only the entry point and the effort change.

## A. No documentation

Knowledge lives in people's heads (client, domain experts, team).

1. Plan capture sessions with the right people (see [capture-methods.md](capture-methods.md)): Event Storming or Domain Storytelling for processes and rules, Example Mapping for specific features.
2. Record sessions **with consent**; keep transcripts as Evidence with timestamps and speakers.
3. Curate decisions, rules and terms from the sessions into the authoritative textual source, as `draft` items for the owners to validate.
4. Start the Glossary early; it prevents most misunderstandings.
5. Every open question becomes a Knowledge Gap.
6. Continue with steps 3-8 of the procedure.

## B. Documented but dispersed

Knowledge exists but is spread across tools, for example: a wiki for vision, rules and technical aspects; a work item tool for epics, features, stories and tasks; a visual board for diagrams; static files such as PDFs, images, spreadsheets and client documents.

1. Run the knowledge audit: build the source registry (what, where, owner, freshness, access method).
2. Assign authority per artifact class; resolve overlaps with the user.
3. Define the key convention and key registry; link items with native links and tags.
4. Find contradictions between sources and record each one as a Knowledge Gap; do not pick a winner silently.
5. Plan adapters per source and the projection (Tier 1 or Tier 2).

This is the scenario where a semantic projection usually pays off, because several sources and multimodal content are involved.

## C. Centralized

Most knowledge lives in one governed system.

1. Run a light audit: confirm there are no hidden secondary sources (shared drives, spreadsheets, chat exports).
2. Check that items follow the knowledge types and the common record; propose fixes as drafts.
3. One adapter is usually enough; Tier 1 (deterministic index) may be sufficient.

## Mixed situations

Real organizations mix scenarios (a well-documented product area next to an undocumented one). Apply the scenario per area, and record which scenario was used for each area in the source registry.
